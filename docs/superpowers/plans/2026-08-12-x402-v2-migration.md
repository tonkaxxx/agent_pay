# AgentPay x402 v2 Migration Plan

> Status: approved for implementation on 2026-08-12.

## Goal

Replace AgentPay's custom `402 JSON -> ERC-20 transfer -> X-Payment-Tx` protocol with the official x402 v2 stack while preserving automatic payment, policy controls, observability, idempotency, and explicit Base mainnet safeguards.

## Product boundary

- Support `exact` USDC payments on Base (`eip155:8453`) and Base Sepolia (`eip155:84532`).
- Use the official `@x402/*` v2 packages and standard `PAYMENT-REQUIRED`, `PAYMENT-SIGNATURE`, and `PAYMENT-RESPONSE` headers.
- Add Payment Identifier and Bazaar discovery extensions.
- Use `https://x402.org/facilitator` for testnet and CDP facilitator credentials for production.
- Do not retain the legacy `X-Payment-Tx` path.
- Defer `upto`, batch payments, Permit2, Solana, a self-hosted facilitator, and Bazaar UI/search.

## Public client API

Rename the package to `@agentpay/client` version `0.2.0` and expose a signer-first API:

```ts
type AgentPayNetwork = "eip155:8453" | "eip155:84532";

interface AgentFetchConfig {
  signer: ClientEvmSigner;
  networks: readonly [AgentPayNetwork, ...AgentPayNetwork[]];
  maxPaymentUsdc: string;
  authorizePayment?: (context: PaymentAuthorizationContext) => boolean | Promise<boolean>;
  paymentIdFactory?: (request: Request) => string;
  onPaymentEvent?: (event: PaymentEvent) => void | Promise<void>;
}
```

The authorization context includes the real request URL, payment ID, `exact` scheme, CAIP-2 network, numeric chain ID, recipient, official USDC token, normalized price, and base-unit amount. Policy failures fail closed. Observer failures do not affect payment execution.

Events are `payment_required`, `payment_authorized`, `payment_settled`, and `payment_failed`; settled events include the transaction hash, while failures identify `parse`, `policy`, `sign`, `verify`, `settle`, or `error` stage.

Remove raw private-key, RPC URL, confirmation, retry, transaction callback, and custom payment runtime options from the SDK.

## Public server API

Rename the package to `@agentpay/server` version `0.2.0` and expose:

```ts
interface CreateAgentPayServerOptions {
  facilitator: FacilitatorClient;
  networks: readonly [AgentPayNetwork, ...AgentPayNetwork[]];
}

createAgentPayResourceServer(options): x402ResourceServer;

createAgentPayRoute({
  network,
  priceUsdc,
  payTo,
  description,
  mimeType?,
  paymentIdentifier?: "optional" | "required" | false,
  discovery?: { outputExample: unknown },
}): RouteConfig;
```

Routes use `exact` and official USDC only. A decimal price such as `0.01` is converted to x402's `$0.01` price expression. Re-export the official Express middleware and the types needed by consumers. Delete the custom receipt verifier, replay store, and legacy header constant.

## Idempotency

Provide `PaymentIdempotencyStore`, an in-memory implementation, a Redis implementation, and `withPaymentIdempotency(handler, options)`.

- Pending lease default: 60 seconds.
- Completed replay default: 3600 seconds.
- Same payment ID and payload returns the original cached response, including `PAYMENT-RESPONSE`.
- Same payment ID and a different payload returns HTTP 409 with `payment_identifier_conflict`.
- A concurrent matching request returns HTTP 425 with `payment_in_progress` and `Retry-After: 1`.
- Redis state changes use atomic Lua/CAS operations under `agentpay:idempotency:v2:`.
- Cache status, safe headers, base64 body, and settlement data; never persist raw payment signatures. Store only a SHA-256 fingerprint.
- Release the pending lease on verification, settlement, or handler failure.

## Application migration

- Update CLI examples to signer-first x402 v2.
- Require both `--execute` and `ALLOW_MAINNET_PAYMENTS=true` for every Base mainnet payment path.
- Keep the mainnet example price fixed at `$0.01`.
- Migrate the Next.js premium endpoint to the official resource server and CDP facilitator configuration, with idempotency outside the paid handler.
- Update package aliases, Next transpilation, Docker build inputs, environment examples, README, docs, landing copy, and tests.
- Mark historical v1 design documents as superseded instead of rewriting their history.

## Execution order

1. Package names, versions, and pinned x402 dependencies.
2. Client wrapper, policy enforcement, extensions, and event stream.
3. Server resource/route factories and official middleware exports.
4. In-memory and Redis idempotency plus response replay wrapper.
5. CLI examples and mainnet safeguards.
6. Web premium route and configuration.
7. Documentation and marketing copy.
8. Unit, type, build, and end-to-end verification.
